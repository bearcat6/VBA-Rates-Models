# CMSスプレッド評価設計

## 目的

`05_CMS-Spread` は、CMSおよびCMSスプレッド評価に関する設計を扱うドキュメント領域です。

現時点での実務的な中心は、CMS関連評価で利用するスワップション・ボラティリティの保持・補間です。

CMSスプレッド取引の本格的な評価ロジックは、今後の拡張対象とします。

## 役割

このモジュールの主な役割は以下のとおりです。

- ATMスワップション・ボラティリティ行列を保持する。
- Expiry × Tenor のボラティリティ点を補間する。
- CMS convexity adjustment で利用するボラティリティ入力を提供する。
- 将来的に、CMS取引・CMSスプレッド取引の商品条件を表現する。
- 将来的に、convexity adjustment および評価ワークフローを実装する。

## 現在の主なクラス

| クラス | 役割 |
|---|---|
| `clsATMSwaptionVol` | ATMスワップション・ボラティリティ行列を保持し、補間値を返すクラス |

## 将来候補クラス

| クラス | 役割 |
|---|---|
| `clsCMSSpreadTrade` | CMSスプレッド取引の商品条件を保持するクラス |
| `clsCMSLeg` | CMSレッグを表すクラス |
| `clsCMSSpreadLeg` | CMSスプレッドレッグを表すクラス |
| `clsCMSConvexityAdjustment` | convexity adjustment を計算するクラス |

## 依存関係のルール

許容する依存関係：

```text
05_cms_spread -> common
05_cms_spread -> 01_discount_curve
05_cms_spread -> 03_sabr
```

将来的に許容する可能性がある依存関係：

```text
05_cms_spread -> 02_ois_swap
```

ただし、OISスワップのスケジュール生成やアニュイティ計算を明示的に再利用する場合に限ります。

## 設計上の注意点

現時点では、`clsATMSwaptionVol` はCMS関連評価で使うことを想定して、この領域に置きます。

ただし、ATMスワップション・ボラティリティが他のモデルや分析でも広く使われるようになった場合は、将来的に以下のような独立領域へ移すことも検討します。

```text
market_data
volatility
swaption_vol_surface
```

## CMSスプレッド評価の将来像

将来的な評価フローは、概ね以下を想定します。

```text
1. 割引カーブを取得する
2. スワップション・ボラティリティを取得・補間する
3. 必要に応じてSABRスマイルを利用する
4. CMSレートまたはCMSスプレッドのconvexity adjustmentを計算する
5. キャッシュフローを生成する
6. 割引カーブでPVを計算する
```

CMSスプレッド評価では、割引カーブ、スワップション・ボラティリティ、SABRスマイル、商品キャッシュフローが関係します。

そのため、`05_CMS-Spread` は最下流の評価モジュールとして位置づけ、上流の共通部品や市場データ処理を再利用する設計とします。

## 他モジュールとの関係

- 割引計算は `01_Discount_Curve` を利用します。
- スマイルや密度の処理は `03_SABR` を利用します。
- OISスワップ関連処理は、必要な場合に限り `02_OIS_Swap` から再利用します。
- Hull-White 1F は将来カーブシミュレーション用途であり、CMSスプレッド評価ロジックとは直接結合しない方針とします。
